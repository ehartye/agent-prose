# AI Style Audit Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use h-superpowers:subagent-driven-development to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tiered, no-verdict audit of default-model prose habits (`prose audit`), a measured human false-positive rate, and a `prose-audit` skill.

**Architecture:** Detectors as small pure functions over parsed blocks with source-cited patterns; reuse the existing era-tagged lexicon and `ai.artifact` patterns; a separate command so `lint` stays quiet; a measurement script that runs the same code over a public human sample and a model sample.

**Tech Stack:** Node 24 running TypeScript directly, zod, commander, vitest (all existing). No new dependency.

Design: `docs/superpowers/specs/2026-10-03-ai-audit-design.md` (source of truth for tiers, families, wording rules and the measurement protocol).

**Working agreements for every task**
- Branch `ai-audit`; never commit to `main`. TDD: failing test first, quote the failing line, then implement. Never weaken a test silently; list every changed expectation.
- Match surrounding style. Read `src/measure/{lexicon,index,style}.ts`, `src/lint/evaluators.ts` (the `ai.*` evaluators), `craft/lexicon/ai-tells.json`, `craft/references.json`, `src/commands/document.ts` and a command test for conventions.
- Run `npx vitest run`, `npm run typecheck`, `npm run refs:check` before each commit; commit style `feat:`/`test:`/`docs:`; end commits with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Tests never touch the real home; no private paths or notes references in committed files (a test enforces it; the private notes tool's name must not appear, 'Wikipedia' is fine).
- Forbidden outputs anywhere in code, docs and skill: an authorship verdict or probability, a numeric 'AI-ness' score, 'likely AI', 'AI-generated' as a conclusion about a text.

### Task 1: Detectors and `prose audit`

**Files:** Create `src/audit/{detectors,cluster,report}.ts`, `src/commands/audit.ts`, `tests/audit-detectors.test.ts`, `tests/audit-cli.test.ts`, `tests/golden/audit-*.json` (via the golden helper). Modify `src/cli.ts`, `craft/references.json` (add any source the audit cites that is missing: Kobak et al. 2025, Juzek and Ward 2024, Liang et al. 2023 and 2024, Reinhart et al. 2025, Russell et al. 2025, Freeburg 2026; use the exact URLs from the sources, `kind` from the allowed enum, notes saying abstract-only where true), `REFERENCES.md` via the repo's command, README.

- [ ] Detectors per the spec table, each `(blocks, ctx) -> Finding[]` with `{ tier, family, line, text, eras?, models?, why, direction }`: hard (reuse the `ai.artifact` patterns; add chat residue and cutoff disclaimers), the soft families listed (era vocabulary via the existing lexicon with exact words only; copula avoidance; promotional; undue significance; trailing participle analysis; negative parallelism; weasel attribution with no nearby citation marker; the 'Despite ... challenges' conclusion; closing 'Overall,' or 'In conclusion,' opener; inline-header bullets; emoji at the start of headings or bullets; Title Case headings; mechanical boldface), and the measured values (em dashes per 1,000 words, sentence-length variation, triplet lists per 1,000 words, copula `is/are` share). Spans are at most 120 characters. Code blocks, inline code and block quotes are excluded. Each detector has a plain-sentence `why` and a revision `direction` that is never a replacement phrase.
- [ ] `cluster.ts`: `clusterOf(findings, words, threshold)` -> `{ met, families, softPerThousand, threshold }`; the default threshold constants live in one file with a comment that they are conventions awaiting the calibration of Task 2 (initial placeholder values: at least 3 distinct soft families and at least 4 soft findings per 1,000 words; Task 2 replaces them with the calibrated values).
- [ ] `report.ts` and the command: JSON by default with `{ path, form, words, tiers: { hard, soft }, measured, cluster, summary, limits, lexicon: { reviewed } }` and `--text`. `summary` is one of the two sentences in spec Principle 1. `limits` is the standing text (authorship cannot be shown from style; a clean result proves nothing; plain and non-native writing trigger some detectors in published research and are not flagged here; numbers are conventions). Forms: Fountain and dialog report hard artifacts and vocabulary only; verse forms are skipped with a note; non-Markdown formatting detectors are off.
- [ ] Tests: each detector matches its own examples, rejects near-misses and a human-writing counter-example (write at least two per family, taken from ordinary human prose styles, e.g. a legitimate 'not X but Y' correction, a real citation after 'experts argue [3]'), ignores code and quotes; the cluster rule at and just below the threshold; the output shape; a test asserting the limits text contains 'authorship' and 'does not' and that no output string contains 'likely AI', 'AI-generated' or a percentage sign in the summary; a golden for a model-like paragraph and a golden for a plain human paragraph; verse forms skipped; markdown versus text formatting detectors; `--form` override.
- [ ] Commit.

### Task 2: Measurement harness and calibration

**Files:** Create `scripts/audit-measure.mjs`, `docs/research/2026-10-03-ai-audit-measurement.md`; modify `src/audit/cluster.ts` constants and its test.

- [ ] A script that takes a directory of `.txt` files per group (human, model-plain, model-clean) and a split seed, runs the audit's detectors in-process, and prints per-family flag rates, soft findings per 1,000 words (mean and percentiles), and the cluster rule's flag rate with Wilson 95% confidence intervals, separately for the calibration half and the held-out half.
- [ ] Data (kept outside the repo, aggregate numbers only are committed): download arXiv abstracts from 2018 to 2021 across several categories through the public arXiv API (several hundred; record ids and a fetch date; be polite with request rates); have Claude write abstracts for the same titles with a plain prompt (no style instruction) and, for a smaller subset, with an instruction to avoid model clichés and write like a careful human. Use subagents for generation in batches; do not let a generator see the audit's patterns.
- [ ] Calibrate the cluster threshold on the calibration half so the human false-positive rate is at most 5%, then report the held-out numbers honestly (including when they are worse than the target), the per-family human flag rates (a family that flags many human abstracts is noted or dropped from the cluster count), and the share of model abstracts that meet the cluster for each prompt. Update the default threshold constants in `cluster.ts` to the calibrated values with the measured rates in the comment.
- [ ] The write-up states the limits plainly: one genre, one model family for the model sample, the human sample includes unknown-nativeness authors, numbers are for these samples only, no claim about authorship.
- [ ] Commit (the script, the write-up, the constants; no raw data).
